- gqlgen toolchain note (updated 2026-04-28 after the passkey regen): the project pins gqlgen runtime at v0.17.60 in `go.mod` but the v0.17.60 generator has a prelude template bug — running `gqlgen generate` against it regenerates `prelude.resolvers.go` with invalid receiver types. The repo carries a hand-patched `prelude.resolvers.go` (using `inputValueResolverImpl`/`typeResolverImpl` wrappers) and ships `src/graphql/gqlgen.yml` with `skip_validation: true` so future generate runs at least write files. **Operational regen workflow** (used to wire the GraphQL passkey runtime): from `src/graphql/`, run `go run github.com/99designs/gqlgen generate` inside `golang:alpine`; gqlgen will overwrite `generated.go` / `models_gen.go` / `schema.resolvers.go` and emit a broken `prelude.resolvers.go`; restore the hand-fixed prelude from `git`, strip the gqlgen-emitted `/* … */` "preserve" block at the bottom of `schema.resolvers.go` (the helpers and per-type resolver methods live in `resolvers_helpers.go` instead so they survive regens), and replace any panic-stub resolvers gqlgen wrote into `schema.resolvers.go` with the real implementations from earlier history. The model bindings in `gqlgen.yml` (APIToken/User/Notification/SavedLocation/Setting → `models.*`) are required so the regen reuses the project's shared structs instead of generating duplicate types; without them gqlgen drops the custom resolver interfaces and breaks the `sql.Null*` → `*time.Time` / `*string` conversions. v0.17.83/0.17.84 fix the prelude template differently but introduce a breaking `executableSchema.Complexity` signature change, so they're not a drop-in replacement for the runtime — keep the runtime at v0.17.60 until the project is ready to do a coordinated runtime bump and re-resolve the breakage in any custom executableSchema callers.
